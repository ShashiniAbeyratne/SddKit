## SDD Workflow

Always follow this sequence. **Never write implementation code before tasks.md is approved.**

```
init → constitution → specify → clarify → plan → analyze → tasks → implement → review → commit
```

| Phase | Skill | Output |
|---|---|---|
| 0 | `/sdd-init` | Project scaffold + `.sdd/memory/project.md` |
| 1 | `/sdd-constitution` | `.sdd/memory/constitution.md` |
| 2 | `/sdd-specify <idea>` | `.sdd/specs/<NNN>-<slug>/spec.md` |
| 3 | `/sdd-clarify` | `.sdd/specs/<NNN>-<slug>/clarifications.md` |
| 4 | `/sdd-plan <notes>` | `.sdd/specs/<NNN>-<slug>/plan.md` + `research.md` |
| 5 | `/sdd-analyze` | `.sdd/specs/<NNN>-<slug>/analysis.md` |
| 6 | `/sdd-tasks` | `.sdd/specs/<NNN>-<slug>/tasks.md` |
| 7 | `/sdd-implement` | Implementation code |
| 8 | `/sdd-review` | Drift report |
| 9 | `/sdd-commit` | Commit + PR description |
